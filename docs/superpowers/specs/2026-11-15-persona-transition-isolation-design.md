# 人格切换与功能回归清单设计

## 意图

降低切换人格后旧助手风格继续影响新回复的概率，同时保留聊天界面历史、用户消息和相关上下文，并建立可重复的功能回归清单。

## 目标

- 网关请求继续携带最近的用户消息，保留用户提供的事实和任务上下文。
- 只把明确标记为当前人格版本的助手回复作为模型对话历史发送。
- 对无法确认人格版本的旧助手回复采取保守策略，不继续转发给模型。
- 每轮人格规则明确撤销旧人格规则，同时允许使用对当前任务有帮助的用户事实。
- 保留 Codex 原聊天及历史；不宣称能够删除已进入 Codex 上下文的旧提示词。
- 建立覆盖现有启动、人格、作用域、平台、对话、安全和 UI 能力的回归清单。

## 非目标

- 不清空或重写 Codex 聊天记录。
- 不改造平台 Hook、会话协议或 API 适配器。
- 不改变现有作用域语义；多网页标签共享服务端启用状态作为已知限制记录。
- 不承诺模型完全遵循新人格，或旧聊天内容不再产生任何影响。

## 方案

沿用现有版本标记机制和当前人格上下文注入。相比删除所有历史或尝试改写模型上下文，这种方案保留用户消息及 UI 记录，只过滤来源人格不明或已过期的助手回复；它不需要新增依赖或改变聊天协议。

## 验收

- 用户历史消息仍被发送给模型。
- 当前人格版本的助手回复仍被发送给模型。
- 旧版本及无版本标记的助手回复不被发送给模型。
- 页面仍显示原有聊天记录，切换时不清空当前对话。
- Codex 后续 Hook 上下文说明旧人格规则不再生效、用户事实与相关上下文仍可使用，并明确不能清理平台已有历史。
- 功能清单中的每项能力均有实现位置、测试或明确的人工验收方式。
