# 第 N 人格接入 Codex 设计

## 意图

让第 N 人格应用中选中的人格影响 Codex 桌面端后续回复，同时保留现有聊天记录。人格规则是模型上下文中的指令，不修改模型本身。

## 目标

- 网页应用与 Codex 集成读取同一份用户级“当前人格”状态，避免各自状态不一致。
- Codex 每次提交用户消息时读取当前人格规则，并将其作为额外上下文提供给模型。
- 保留各人格独立的 `SKILL.md`，信达雅完整流程只属于信达雅。
- 仅交付并验证 Windows Codex 桌面端接入；其他 AI 暂不在本次范围内。
- 不清除或重开聊天。旧信息仅在用户明确提及并许可时才尝试调用。

## 非目标与限制

- 不修改 Codex 或其他模型的权重，也不接管桌面端界面。
- 不通过第 N 人格网页的 API 请求影响 Codex 桌面端。
- Codex Hook 可以追加当前人格规则，但不能从已有聊天上下文中移除旧助手消息。因此“旧发言绝不产生任何影响”无法保证；规则只能要求不模仿旧人格，并按用户许可处理历史信息。

## 方案比较

1. **Codex 插件 Hook + 现有本地状态（采用）**：保留 UI 为切换入口；同步 `UserPromptSubmit` Hook 每轮通过本地服务读取状态并追加当前人格规则。能影响 Codex 后续模型请求，但需用户审核并信任 Hook。
2. **仅使用 Skill**：最轻量，但网页切换不能可靠地自动影响 Codex。
3. **仅使用现有兼容 API**：不需改 Codex 设置，但只影响网页自身发往该 API 的请求。

本次只做方案 1；不扩展其他 AI 的安装和兼容层。

## 设计边界

- 复用现有 `server/data/current.json`、`/switch` 和人格 `SKILL.md`，不增加第二份状态。
- 新增 `/codex/context`，只返回白名单人格的当前规则，不包含 Key、聊天记录或其他用户数据。
- Codex 插件的 `UserPromptSubmit` Hook 访问本机服务并返回 `additionalContext`。服务未启动时给出诊断，不缓存或继续使用旧人格。
- 安装和信任由用户确认；不自动修改真实 Codex 配置。
- Hook 注入的当前规则应明确覆盖旧人格的语气和结构；用户未明确提及并许可前，不主动提取或引用其他聊天中的旧信息。

## 验收

- 网页切换人格后，Codex 下一轮输入能收到对应规则；不需要 API Key。
- Hook 不读取或输出 API Key；损坏、缺失、未知人格状态有可诊断的安全回退。
- 聊天记录保持可见，切换不清空或新建聊天。
- 用真实浏览器验证应用切换；用隔离的 `CODEX_HOME` 和本地假状态验证插件及 Hook，不改写用户真实 Codex 配置。
- 不把提示词层面的隔离描述成对旧上下文的绝对屏蔽。
