# 统一人格控制台 UI 设计

## 目标

把现有页面统一为一个清晰、克制的“人格控制台”，让用户第一眼看懂当前人格、可切换人格和对话工作区，同时不改变任何人格切换、聊天、API 或 Codex Hook 行为。

## 设计边界

- 只修改 `index.html` 的视觉、布局、响应式、可访问性标记和静态文案呈现。
- 保留现有 JavaScript 数据、函数、请求路径、请求体、状态变量和事件行为。
- 不增加框架、组件库、构建步骤或运行时依赖。
- 不清空聊天、不改变人格覆盖规则、不改变本地状态和 API Key 存储方式。
- 当前版本使用统一主题；只预留语义化 CSS 变量，后续再实现个人主题定制。

## 视觉系统

- 背景使用中性石墨黑，面板采用两级灰阶，避免原页面紫色占比过高。
- 主操作色使用冷青色；绿色只表示服务在线，琥珀色只表示等待或离线。
- 所有人格卡片使用同一结构和颜色系统，仅通过图标、名称和选中状态区分。
- 选中人格以清晰边框、轻量底色和“当前生效”状态标记表示，不做整页换色。
- 减少装饰渐变和阴影，强化信息层级、边界、对齐和可读性。

## 布局

- 桌面端保留侧栏、主工作区和人格状态栏，但统一栅格、间距与面板样式。
- 人格库在宽屏显示五列，中等宽度显示三列，手机显示单列，避免窄卡片文字拥挤。
- 对话区作为主要工作区，状态栏作为辅助信息，不使用卡片套卡片的装饰结构。
- 移动端隐藏侧栏，顶部状态与设置按钮保持可操作，面板按当前状态、人格库、对话区顺序自然排列。

## 可访问性与质量

- 所有交互控件最小高度 44px，并提供明确的 `:focus-visible` 状态。
- 正文和关键状态文字不低于可读尺寸，提升对比度。
- 为页面补充描述、图标和必要的语义标签；API 设置使用原生表单结构。
- 支持 `prefers-reduced-motion`，禁用非必要位移和过渡。
- 用真实浏览器验证桌面、平板和手机宽度，以及人格切换、聊天保留、API 设置和键盘操作。

## 方案比较

1. **统一控制台主题（采用）**：视觉稳定，符合当前产品定位，也最容易保证人格切换不干扰上下文。
2. **仅随人格改变强调色**：辨识度更高，但当前会让人格切换带来不必要的视觉干扰，留到个人设置阶段。
3. **每个人格完整换肤**：维护成本高，容易让用户误以为人格是独立会话，本次不采用。
